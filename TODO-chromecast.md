# TODO: Chromecast Audio Output Support

This plan captures the work needed to add OS-independent Chromecast Audio output to sdrtrunk. Each task builds on the previous ones and assumes testing on all three supported desktop platforms.

1. **Audit Existing Playback Stack** – Document how `AudioPlaybackManager`, `AudioOutput`, `MonoAudioOutput`, `StereoAudioOutput`, and `MixerManager` collaborate today, including thread usage, data formats (8 kHz float buffers), and the Swing/JavaFX controls that rely on Java Sound controls for mute and volume. Confirm where duplicate suppression, tone insertion, and metadata broadcasting are anchored.
2. **Define `AudioSink` Abstraction** – Extract an interface (start/stop/write/mute/gain/availability) that captures the operations `AudioOutput` currently performs on `SourceDataLine`. Introduce a concrete `JavaSoundAudioSink` to wrap the current `SourceDataLine` path without changing behavior.
3. **Refactor `AudioOutput` to Use `AudioSink`** – Rework `AudioOutput` so it owns an `AudioSink` instead of a `SourceDataLine`. Ensure scheduling, tone insertion, metadata updates, duplicate handling, and GUI notifications continue to function with the new abstraction. Add defensive hooks for sinks that cannot provide gain/mute controls.
4. **Rework Preferences Model** – Replace `MixerChannelConfiguration` with a more general `PlaybackDevice` model that can represent both legacy mixer-backed outputs and network devices. Update `PlaybackPreference` persistence, serialization, and `MyEventBus` notifications accordingly.
5. **Update JavaFX Preference Editor** – Modify `PlaybackPreferenceEditor` to list both local mixers and discovered Chromecast endpoints. Add UI to refresh the device list, show availability status, and warn the user when the chosen device disappears.
6. **Update Swing Audio Panel** – Adjust `AudioPanel`/`AudioChannelPanel` so they tolerate sinks lacking Java Sound controls. Hide or replace the gain slider when the sink cannot expose `FloatControl`, and surface Chromecast-specific actions (connect/disconnect, cast target name) if needed.
7. **Introduce Chromecast Discovery Layer** – Pull in a Cast control library (e.g., `su.litvak.chromecast.api.v2`) plus JmDNS for mDNS discovery. Implement a service that finds Chromecast Audio-capable devices, monitors availability, and exposes them through the new preference model.
8. **Design Streaming Architecture** – Decide how to deliver audio to Chromecast (push vs pull). Plan for a lightweight embedded HTTP server that serves a continuous stream (likely MP3) and choose a URI scheme the Cast receiver can fetch. Define buffering and reconnection strategy.
9. **Implement Chromecast Audio Sink** – Create a sink that opens a Cast session, launches the default media receiver, and hands it the HTTP stream URL. Handle lifecycle events (play/pause/stop), errors, and device disconnects, and translate mute/volume requests into Cast volume APIs.
10. **Implement HTTP Streaming Server** – Add a small server that exposes each active audio channel as a Cast-friendly stream. Reuse the existing MP3 encoder (`MP3AudioConverter`) or add AAC support if required. Manage per-channel buffers so latency stays acceptable while Cast pulls data.
11. **Add Resampling/Encoding Pipeline** – Integrate `RealResampler` or similar to convert 8 kHz mono floats to the sample rate mandated by Chromecast (44.1/48 kHz). Feed the resampled data into the chosen encoder before enqueuing frames for the HTTP server.
12. **Handle Multi-Channel Semantics** – Decide whether Chromecast targets receive a mono mix of all active channels or separate logical streams. Update `AudioPlaybackManager` so it can direct multiple logical `AudioOutput`s into a single Chromecast sink without breaking duplicate suppression or metadata continuity.
13. **Metadata & GUI Updates** – Ensure identifier metadata and start/stop events still propagate when audio is sent over Chromecast. Consider augmenting the Cast stream with ID3 tags or side-channel metadata so remote receivers display talkgroup info.
14. **Testing & Diagnostics** – Build manual test plans for Windows/Linux/macOS, covering device discovery, reconnects, latency, duplicate suppression, tone playback, and UI controls. Add logging around Cast session state, HTTP streaming health, and resampler statistics to aid troubleshooting.
15. **Documentation & User Guidance** – Update the README/wiki with Chromecast requirements (network visibility, firewall considerations), configuration steps, troubleshooting tips, and known limitations (e.g., no per-channel gain). Provide users with guidance on selecting the correct network interface and verifying Cast connectivity.
