# TODO

1. `BladeRF2QuickTuneManager.captureProfile` increments profile counters before validation, causing slot leaks when capture fails. Delay increment until after the band map is found and RFIC/NIOS writes succeed.
2. [DONE] `TunerManager.tunerStatusUpdated` still calls `start()` for enabled USB tuners, so saved configurations aren’t applied before listeners see the tuner. Switch to `startAndConfigure()`.
3. [DONE] `BladeRFTunerController.setTunedFrequency` updates `mFrequency` prior to hardware retune, so the controller can report a frequency that never applied if the call fails. Only assign after a successful hardware operation (or roll back on failure).
4. `BladeRFVctcxoTrim.getStoredTrim()` caches the SPI value permanently, so `refreshCalibrationCache()`, `invalidateCalibrationCache()`, or a manual DAC write never take effect until the controller is rebuilt. Provide a way to invalidate the cached trim when calibration data changes so `applyStoredTrim()` re-reads the latest value.
5. [DONE] `BladeRFTunerController.setSampleRate` never schedules `scheduleSampleClockInitialization()` when auto sample-clock reprogramming is enabled and the change happens while streaming, so the Si5338 output stays at the previous rate indefinitely. Track that a reprogramming is pending and queue the worker as soon as the stream is quiescent.
6. When `TunerManager` auto-enables the RSPduo slave (lines 445‑449), it still calls `start()` instead of `startAndConfigure()`, so the saved tuning configuration isn’t applied before listeners attach to the slave. Mirror the primary-path fix by invoking `startAndConfigure()` there as well.
7. `USBTunerController.start()` invokes `preStart()` before it checks whether `mDeviceContext` is null, so subclasses overriding the hook will run (and possibly touch the USB context) even when the controller can’t ever restart. Move the `preStart()` call after the null check so extensions only run when the device is actually startable.
8. Tuner frequency controls don’t refresh when the lock state changes: the backend drops `isLockedSampleRate()` when channels stop, but `TunerEditor.FrequencyPanel` only enables/disables on status changes, so the UI can stay greyed out (or vice versa) until the tuner is toggled. See `docs/tuner-frequency-lock.md` for details and fix options (hook the lock events back into `FrequencyPanel.updateControls()`).
9. [DONE] Channel stop requests sent by `PolyphaseChannelManager.stopAllChannels()` couldn’t stop wrapped sources (e.g. `MultiFrequencyTunerChannelSource`), leaving orphaned channels whenever a tuner was disabled. `ProcessingChain.hasSource()` now walks sources implementing `SourceWrapper`, and `MultiFrequencyTunerChannelSource` exposes its wrapped source, so stop requests reach the correct processing chain.
10. High-level plan for reintroducing bladeRF 1 support via the libusb native path is captured in `TODO-bladeRF1-support.md`. Use that checklist when resurrecting the legacy devices.
